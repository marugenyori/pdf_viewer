# 報告：Design Wave Magazine の誌面検索（RAG）用の索引

作業日：2026-10-18。PC の Claude（Cowork）が `docs/PC_RAG_REQUEST.md` の依頼どおりに作った。

## 先にお知らせ：雑誌のファイル名を付け直した

依頼を受ける前に、持ち主の了解を得てフォルダを整理した。
- 雑誌 48 冊を、表紙の発行年月で `Design_Wave_2002_01.pdf` 〜 `Design_Wave_2005_12.pdf` に改名した。2002年1月号〜2005年12月号で、欠けも重複もない
- 雑誌フォルダに紛れていたジョジョ 5 冊（第8・9・15・17・26巻）と、本 1 冊（`SF作家の地球旅行記.pdf`）は外へ移した。`design_ware` フォルダ（2002年7月号の別スキャン）と `ジョジョテスト` フォルダはごみ箱へ送った
- 索引の `file` は新しい名前になっている。雑誌の読んだ位置・しおりは、改名でリセットされている

## 索引の中身

- 置き場所：`ScanSnap Home\Design_Wave_Magazine\rag_index.json`（形式は依頼どおり。`version: 1`）
- 48 冊、8,876 ページ（文字のあるページ 8,872）、17,611,394 文字、40.7MB（gzip で圧縮すると 15MB）
- `source`：`ScanSnap OCR（pdftotext で取り出し、カタカナの誤認識を一部補正）`
- 作業環境に PyMuPDF が入らなかったので、文字の取り出しは pdftotext（poppler）で行った。中身は同じ ScanSnap の OCR の文字だが、行の並び順は PyMuPDF と少し違うかもしれない
- 文字がほとんど取れないページ（30 文字未満）：9 ページだけ。2 ページ目（表紙の裏）や全面広告・写真のページで、問題はない

## 文字の質（ページの画像と見比べた結果）

全体としては、**本文は検索に十分使える**。誤字はあるが、単語の大半は正しく取れている。

- **本文（横書き 2〜3 段組）**：よく取れている。誤りはおよそ 1〜3%。多いのは次のとおり
  - カタカナの「ト」が「l、」「I、」「1、」になる（例「ソフl、ウェア」「16ピッl、」「プラッI、フォーム」）。**索引を作るときに直した**（前後がカタカナのときだけ「ト」に戻す）。「ソフトウェア」は修正前 5,657 → 修正後 5,911 件見つかるようになった
  - 「ハー」が「八一」になる（例「八一ドウェア」137 件）。これも直した（「ハードウェア」3,568 → 3,705 件）
  - 濁点・半濁点と小さい字の取り違え（「プロトタイビング」「ソリユーション」「ボート」「ピット」）。これは直していない
  - 「搭載」→「搭栽」、「構築」→「櫛築」のような、形の似た漢字の取り違えが少しある
- **見出し**：大きな見出しはおおむね正しい。飾り文字の見出しは崩れることがある。ページ上の柱「Design Wave Magazine」は「Design W°C1ve Mqgqzine」のように崩れる
- **図・グラフの中の文字**：ほとんど取れず、意味のない文字の並びになる（「のの”四一一国」のような列が続く）。軸の数字や凡例の一部は取れる
- **表**：セルの文字は取れるが、行と列の対応はばらばらになる
- **ソースコード（リスト）**：崩れる。`0x014f` が `OxO14 f`、`;` が `ノ`、`++` が `十十` などになり、行の順番も乱れる。コードの中の識別子での検索はあまり当てにならない（コードらしいページは全体で十数ページ）

## OCR はやり直さなかった

- 同じ本文を tesseract（`jpn`）で読み直して比べたが、誤りの種類が違うだけで、良くはならなかった（例「60%」が「602%」、「プロトタイピング」が「プロトタイビング」）。1 ページに数秒かかり、全 8,876 ページでは半日以上かかる
- Windows の OCR は、この作業環境からは使えなかった
- そこで ScanSnap の OCR のまま、よくある誤りだけを `clean()` で直すことにした（`tools/build_rag_index.py` に追加。出力の形は変えていない）

## 検索で困りそうな点（アプリ側で考えるとよいこと）

1. **表記ゆれ**：同じ言葉が雑誌の中でも書き分けられている。「インターフェース」3,493 件／「インタフェース」150 件／「インターフェイス」109 件など。AI に検索語を作らせるとき、ゆれも一緒に出させるとよい
2. **濁点・半濁点の誤り**：「ビット」↔「ピット」、「ボード」↔「ボート」。検索のときに濁点・半濁点を無視して比べる（例：文字を NFD に分けて濁点を落とす）と取りこぼしが減る
3. **図の中の文字のごみ**：意味のない文字の並びが多いページは、部分一致で偶然当たることがある。1〜2 文字だけの語は検索語にしないほうがよい
4. **ソースコード**：上のとおり崩れているので、コードの中の名前で探すのは難しい
5. **索引が 40MB ある**：iPhone で読み込むと時間とメモリを使う。毎回読み直さない作りにしておくとよい

## 索引の作り直しかた

PDF が増えたり名前が変わったりしたら、PC で次を実行する（PyMuPDF が入る環境なら依頼どおりの手順でよい）。

```powershell
pip install pymupdf
$env:PYTHONUTF8 = "1"
python tools/build_rag_index.py "C:\Users\yfb31\Documents\icloud同期フォルダ\iCloudDrive\ScanSnap Home\Design_Wave_Magazine" --report
```
